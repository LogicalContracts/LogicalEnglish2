## Verify (run from /work)
```
swipl -q -g main -t halt docs/RK_book/examples/.le_check.pl docs/RK_book/examples/<FILE>.le 2>&1 | grep -v Warning
```
Good output: `ISSUES: none` then `PASS  q=... scn=...` for every test.

```

```

## LE gotchas (learned the hard way — heed these)
1. Concrete entities are BARE constants: lowercase, NO article — `crow`, `bob`, `cheese`.
   Writing `the crow` makes it a VARIABLE (article + common noun). Capitalized `John`, `Alice` are also constants.
2. Two DIFFERENT variables of the same type in one sentence: use qualifier names
   `a first person` / `a second person` (or all-caps ids `a person X` / `a person Y`),
   and co-refer later with `the first person`. A plain repeated `a person`/`the person` is the SAME variable.
3. Rules must be GENERIC (use variables). Put concrete data in `scenario`s.
   Scenario facts should be for BODY predicates; queries for HEAD predicates.
4. Negation: `it is not the case that <sentence>`. Conditional negation: `... unless <condition>`.
   There is NO `then false` integrity constraint — model exceptions with naf or an explicit contrary predicate
   (e.g. `*an animal* cannot fly`).
5. Numeric/date comparison: use system templates (`*X* is greater than or equal to *Y*`,
   `*X* is after *Y*`, `*X* is before or equal to *Y*`, `*X* is *Y* days after *Z*`) — NOT comparative adjectives.
   Dates are written `2021-10-09` and render like `2021-10-9T0:0:0.0`.
6. `or` / `either ... or ...` and `and` mix: indentation/grouping disambiguates precedence — follow
   citizenship.le's layout. When in doubt, split a disjunctive rule into several single-condition clauses.
7. Avoid mutual recursion among rule HEAD predicates when the query leaves arguments unbound;
   it can stop derived answers from enumerating (in fox_and_crow.le we split `holds` vs `has`).
8. Expected answers must be the EXACT canonical strings LE prints. Procedure: write rules + scenario +
   query with placeholder `expects answers ["?"]`; run the harness; when the logic is right the harness
   prints `actual=[...]`; copy those exact strings into `expects answers [...]`.
9. Every template used must be declared under `the templates are:`. A program needs RULES, not only facts.
   Aim for at least one scenario whose query yields a non-empty expected answer.
10. `*Sub* is a *Super*` taxonomy facts go in `the ontology is:` (or the KB). A value's type is its head noun.

## File structure (see references)
```
the target language is: prolog.

the templates are:
...

the ontology is:        % optional
...

the knowledge base <name> includes:
...rules and KB facts...

scenario <name> is:
...body-predicate facts...
<queryname> expects answers ["...", "..."].

query <name> is:
...head-predicate goal...
```

## REQUIRED header in every .le file (top, as `%` comments)
- `Origin:` book chapter + section/subsection + example name, cited precisely.
- `Last verification:` whether the final harness run flagged open issues — say "no open issues
  (no errors/warnings; all tests pass)" ONLY if `ISSUES: none` and every test `PASS`; otherwise summarize what remains.
